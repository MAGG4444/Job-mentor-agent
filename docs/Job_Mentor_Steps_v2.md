## M1 三题文字面试、本地保存与恢复

当前状态：开发及离线测试已完成，真实模型端到端手动验收待完成。以下操作和任务保留作为实现与验收记录。

### M1.1 明确用户流程

首次运行读取简历与 JD → 复用现有函数生成三个问题 → 校验 → 保存会话 → 一次显示一道题 → 用户输入回答 → 保存 → 下一题。第三题提交后标记完成，打印记录位置。

本阶段没有追问、评分、训练或前端。它验证的是“用户真正完成一次有记录的面试”。

### M1.2 建立数据契约

新增会话结构，使用 Pydantic 校验。字段至少包括：

| 字段 | 要求 |
| --- | --- |
| schema_version | 固定初版值，为未来迁移预留 |
| session_id | 程序生成 UUID |
| created_at / updated_at | 带时区的时间 |
| status | in_progress、paused、completed |
| source_snapshot | 当次简历/JD 文本，不只记录可变路径 |
| model_config | provider、model、reasoning effort；绝不包含 key |
| prompt_version | 标识本轮出题规则 |
| questions | 保留现有三个问题及证据字段，添加稳定 question_id |
| answers | question_id、回答原文、提交时间 |

可以由已提交回答计算当前题号；如果保存游标，必须校验与回答一致。空白回答提示重新输入；“不知道”是合法回答，不能强迫用户编造答案。

### M1.3 实现存储

数据根目录由配置或项目位置确定，不依赖启动时的当前目录。首版保存到 data/interviews/<session_id>.json。

先写同目录临时文件，成功后替换目标文件；失败则保留旧记录并显示错误。不得在保存失败后显示“提交成功”或继续下一题。生成问题后首次保存失败，也不能开始可回答的会话。

分离存储函数、会话推进函数和 CLI 交互。异常处理保留用户已输入的回答以便重试，不吞掉磁盘权限或格式错误。

### M1.4 实现退出和恢复

支持 /exit 和 Ctrl+C；确保已提交内容落盘。未提交的终端输入不承诺保存。展示 session_id 与恢复命令。

增加 --resume <session_id>。校验 UUID，只允许访问配置数据目录中的对应文件；不存在、JSON 损坏或不支持的版本要明确报错，不创建新会话覆盖原记录。

恢复时直接加载已保存的题目与回答，显示下一道未答题。不得重新出题、调用模型或要求 API key；这要求配置与模型实例化按需执行。已完成会话只显示完成状态与记录位置。

### M1.5 有针对性的离线检查

使用可注入的 fake question generator 与临时数据目录，验证：

1. 新会话恰好三题，生成后即有记录。
2. 空白输入不推进；合法回答保存后推进。
3. 退出再恢复，题目和已提交回答一致，不重复生成。
4. 不提供 key 的恢复流程仍可用，模型生成函数调用次数为零。
5. 已完成会话不能重复回答。
6. 保存失败不推进；损坏记录不被覆盖；非法 ID 被拒绝。

不需要重新测试天气工具，不需要为每个字段编写重复实现逻辑的测试。若使用 pytest，先检查是否已有；仅安装本阶段确需的开发依赖并更新项目声明。

### M1.6 待实现后才能执行的命令

入口建议为 examples/interview_session.py；如现有项目已采用其他名称，统一更新 README 与本节命令。

完成离线检查后，你手动进行一次新会话：答第一题、退出、恢复、答剩余题，检查 JSON。记录实际调用次数；没有观测到用量就写不可用，不估算成事实。

## M2 追问与证据反馈

### 前置条件

M1 已验收。明确一个首批岗位范围，准备六类虚构回答：完整、模糊、不知道、矛盾、偏题、请求提示。

### 开发顺序

1. 在 knowledge/rubrics/ 编写并人工检查三份短标准：个人贡献、技术解释、方案取舍。每份包含 id、版本、观察证据、不能据此推断的结论。
2. 将主问题与追问统一为 Turn；记录 turn_id、question_id、parent_turn_id、类型和回答。
3. 模型提出 follow_up 或 next_topic，程序执行每个主问题最多两次追问的限制。用户不会时记录原话，面试阶段不提供参考答案。
4. 先保存回答再生成追问。模型失败保留回答并标记待生成；重试仅重新生成，不重复提交答案。自动重试维持关闭，手动重试有明确入口。
5. 判断是否引入 LangGraph：若分支、等待与恢复逻辑已难管理再引入。书面确定 JSON/数据库与 checkpoint 谁持有权威状态，不能靠两边各写一次保证一致。
6. 面试结束后单独评估，不能出完题就给能力结论。

反馈项包含 finding_id、能力主题、证据状态、turn_id、quote、rubric_id/version、解释、下一动作。校验 quote 是该 turn 的回答片段，标准来自本轮实际输入。无效引用不发布为可信报告。

### 验收

追问上限由代码保证；失败后原回答仍存在；提前结束标注覆盖不足；没有考察的能力列为未考察。人工检查至少六类样例的判断是否克制、解释是否合理。引用校验通过不等于语义评估正确。

## M3 训练计划、练习与复测

1. 从有效发现项生成最多三个优先任务，包含 finding_id、具体动作、预计用时、完成标准和复测主题。
2. 用户可以接受、修改或暂缓任务；任务状态与能力判断分离。
3. 新建练习记录，允许提示与示范，明确区别于面试记录。
4. 新建 mode=retest 的面试，绑定原任务；考察相同能力，题面或限制条件不同。
5. 报告展示原回答和复测回答的证据比较，不将背诵训练答案判定为独立掌握。
6. 增加 Markdown 报告与 JSON 导出，不包含配置密钥。

验收：从一次诊断可以走到任务、练习、复测；每项任务可追溯；比较条件不足时显示证据不足。先完成终端闭环，再进入网页开发。

## M4 接入本地网页

### M4.1 整理服务模块

根据 Plan v2 的目标结构，将可复用逻辑迁入 src/job_mentor。继续使用根目录 pyproject.toml，不建立另一套 backend Python 项目。现有 CLI 作为薄入口调用服务层。每次迁移先检查导入、离线流程和数据兼容，不边迁移边重写全部业务。

如果 JSON 已难以管理多岗位与任务关联，再引入 SQLite：备份旧文件、定义 schema 版本、编写可重复验证的迁移、检查数量及引用关系；成功前不删除旧数据。

### M4.2 本地 API

新增 FastAPI 依赖与入口，模型仅在需要时创建。先实现并测试以下接口；名称可以调整，但 README、前端与测试必须一致。

| 接口 | 职责 |
| --- | --- |
| GET /api/health | 本地服务健康状态，不调用模型 |
| POST /api/workspaces | 建立岗位准备空间 |
| POST /api/workspaces/{id}/materials | 保存文本资料和版本 |
| POST /api/workspaces/{id}/interviews | 建立面试 |
| GET /api/interviews/{id} | 读取当前状态 |
| POST /api/interviews/{id}/answers | 保存回答并推进 |
| POST /api/interviews/{id}/retry | 仅重试待生成步骤 |
| GET /api/workspaces/{id}/report | 读取反馈和计划 |

增加练习、复测和导出接口以覆盖 M3。提交使用 request_id 与版本检查，防止双击或并发产生两条回答；长时间模型请求不占用数据库写事务。

### M4.3 React 页面

仅在确认 frontend 不存在后初始化。安装命令与依赖版本届时按实际环境和官方文档核实，提交已验证的 lockfile，不照抄旧版重新安装整个项目。

按顺序实现资料、面试、反馈计划、练习复测、概览、设置。先文本粘贴，再考虑文本型 PDF。表单失败保留输入，刷新从后端恢复，等待中防止重复提交。

密钥只由后端读取。设置页展示已配置/未配置状态，不返回密钥。缺少 key 不阻止查看历史记录。上传文件采用内部 ID 命名、检查大小与路径；无文本 PDF 提示粘贴内容。

### 验收

浏览器完成 M1–M3 全流程；刷新不丢已提交答案；断网错误可恢复；跨会话 ID 不可错误关联资料；旧 CLI 仍可使用。服务绑定 127.0.0.1。

## M6 可选 RAG 增强

先用三份短标准按能力标签加载，不因为项目使用 agent 就强制建立向量库。

当标准资料增多、固定加载遗漏依据或历史回答检索确有需求时：整理来源与许可 → 建立标签/关键词基线 → 定义检索返回结构 → 再尝试向量方案。

记录 chunk_id、来源、版本、内容哈希和索引配置；用户历史按 workspace 过滤。删除资料同步清理派生索引。远程 embedding 会发送文本，应在功能说明中写清。

准备同一批检索问题和回答，对比无额外资料、标签资料和向量检索；检查相关性、引用正确性、技术错误及训练建议具体性。只有实际结果支持才设为默认。索引不是原始数据权威来源。
