# Job Mentor 项目计划书 v2

本版依据当前对话中的开发报告修订。原版保留；后续开发以本版与配套 Steps v2 为准。进度来自你提供的本地 Codex 报告，不代表本轮已直接检查 Windows 仓库。本文是计划，不代表以下待开发文件已经存在。

## 1. 项目定位

开源、本地运行的求职 Mentor。用户 clone 仓库、配置自己的模型 API key，启动后使用本地浏览器页面；简历、JD、面试记录与训练计划保存在自己的电脑。

核心闭环：具体岗位与经历 → 诊断面试 → 有依据的反馈 → 专项练习 → 新题复测。先帮助用户发现和改善本轮表现，不承诺录用结果，也不根据一次模拟面试判断综合实力。

与普通聊天的差异应体现在可恢复的流程、可核验的证据、固定评价标准、持续训练记录和复测比较。多角色、语音或 agent 数量本身不构成不可替代性。

## 3. MVP 边界

首版包含：文本简历与 JD、三个主问题、受限追问、持久化与恢复、证据反馈、最多三个训练任务、专项练习、同能力新题复测、Markdown/JSON 导出、本地浏览器界面。

优先聚焦一个你能够检查答案质量的软件岗位。前端岗位可以作为候选，但岗位范围应在准备评价标准时明确。

首版不要求：自动投递、岗位爬虫、语音、多人角色、OCR、账号系统、云部署、向量数据库。文本型 PDF 上传可在文本闭环稳定后补充，不阻塞首次可用版本。

## 7. 数据与评价规则

每次面试保存输入快照、问题与回答、时间、状态、模型与提示版本。简历变动不能悄悄改变历史面试的依据。

反馈必须区分“本轮已展示”“需要澄清”“需要练习”和“未考察”。简历没写不等于不会；回答引用真实也不等于解释正确，需要人工检查标准与反馈质量。

发现项至少关联回答 turn_id、原文片段、评价标准版本与解释。任务关联发现项，给出具体动作、完成标准与复测主题。任务勾选完成不等于能力掌握。

资料本地保存不代表完全离线：调用远程模型时会发送选定文本。前端不接触 API key，日志不保存原始简历或密钥。恢复已有三题会话不应依赖模型服务或有效密钥。

## 8. 页面布局

| 页面 | 主要内容 |
| --- | --- |
| 概览 | 当前岗位、未完成面试、下一项任务 |
| 资料 | 简历、JD、文本预览、用户确认 |
| 面试 | 当前问题、回答框、进度、保存状态、结束按钮 |
| 反馈与计划 | 原文证据、解释、未考察项、最多三个任务 |
| 训练与复测 | 练习指导、提交、新题复测、前后证据 |
| 设置 | 模型配置状态、数据目录、连接检查 |

桌面使用左侧导航与中央工作区。面试阶段不显示标准答案或教学提示；练习阶段允许提示。不展示没有测量依据的准备度百分比。

## 9. 质量与发布标准

确定性测试使用 fake provider 与临时目录，验证流程、保存失败、恢复、次数限制和引用规则。模型质量评估单独记录，包括模糊回答、不知道、矛盾、偏题和完整回答等案例。

真实模型调用只用于必要验收，记录次数、配置和可获取的用量，不自动无限重试。不得为了修纯显示问题反复运行付费测试。

MVP 发布门槛：新目录按说明安装；缺少 key 也能打开已有本地记录；中途退出可恢复；报告引用可定位；练习与复测分离；密钥和私有数据未进入仓库；说明实际验证的平台与限制。
